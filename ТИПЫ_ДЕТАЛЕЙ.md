# Типы деталей

Общая классификация: у каждой детали в `device.json` есть поле `type`. Тип
отвечает на вопрос «что это вообще за штука», а не «из какого она устройства».
Экран тамагочи, дисплей Nokia и матрица консоли — все три `display`.

Зачем: игра обращается с деталями одного типа одинаково (чинит, красит,
подсвечивает), а во вьювере тип красит деталь на схеме — один тип всегда
одного цвета, потому что цвет считается из хеша названия.

## Как этим пользоваться (правило для Клода)

1. Перед тем как назначить детали тип — **прочитай этот файл**.
2. Ищи подходящий тип среди уже записанных. Подходит по смыслу — бери его,
   даже если деталь называется иначе: `lcd_screen`, `display_module` и
   `screen_glass`+матрица — всё это `display`.
3. Ничего не подошло — **добавь новый тип в таблицу**: строка с `type`,
   описанием и примерами id. Только после этого используй его в `device.json`.
4. Тип пишется латиницей, в единственном числе, snake_case: `display`,
   `circuit_board`, `battery`. Не плодить синонимы: `pcb` и `board` — это
   один тип `circuit_board`.
5. Тип обязателен для каждой детали. Совсем непонятная деталь — `misc`.

Правило про синонимы важнее остальных: два названия для одной сущности дают
два разных цвета на схеме и ломают весь смысл классификации.

## Таблица типов

| type | Что это | Примеры id |
|---|---|---|
| `housing_front` | Лицевая часть корпуса, с вырезами под экран и кнопки | `front_shell`, `keypad_bezel` |
| `housing_rear` | Задняя крышка и корпус-ванна, внутренняя сторона | `back_cover`, `rear_chassis` |
| `housing_part` | Прочие куски корпуса: крышка отсека, накладка, заглушка | `top_cap`, `battery_door` |
| `display` | Экран целиком: матрица, модуль дисплея, защитное стекло | `lcd_screen`, `display_module`, `screen_glass` |
| `circuit_board` | Печатная плата с элементами | `main_pcb`, `sub_board` |
| `chassis` | Несущая рама внутри корпуса: металлическое шасси, средняя рамка | `chassis`, `mid_frame` |
| `sensor` | Светочувствительная матрица, датчик изображения | `sensor_module`, `image_sensor` |
| `battery` | Источник питания: банка, таблетка, аккумулятор | `battery` |
| `contact` | Металлический контакт, пружина, клемма питания | `battery_contact`, `spring` |
| `button` | Отдельная нажимная кнопка или клавиша | `button_a`, `btn_cross`, `btn_home` |
| `button_pad` | Клавиатура или крестовина одной деталью | `keypad`, `dpad` |
| `membrane` | Токопроводящая мембрана под кнопками | `keypad_membrane`, `membrane_dpad` |
| `stick` | Аналоговый стик, джойстик | `stick_left`, `stick_right` |
| `trigger` | Курок, бампер, боковая клавиша | `trigger_l1`, `trigger_r2` |
| `speaker` | Динамик, зуммер, пищалка | `buzzer`, `speaker` |
| `antenna` | Антенна, катушка, штырь | `antenna`, `coil` |
| `cable` | Шлейф, провод, гибкая плата | `flex_cable` |
| `fastener` | Крепёж: винт, шуруп, защёлка | `screw_1`, `screw_2` |
| `optics` | Объектив, линза, светодиод, вспышка | `lens`, `led` |
| `mechanism` | Подвижный узел: привод, лентопротяг, шестерни | `tape_mechanism` |
| `media` | Сменный носитель: диск, кассета, картридж, карта памяти | `cd_disc`, `cassette`, `cartridge` |
| `misc` | Не подошло ни подо что | — |

## Кто это пишет

`type` попадает в `device.json` на шаге упаковки атласа (`asset_pack`) — Клод
передаёт его вместе с `id` и `name`. Поменять потом можно двумя способами:
`asset_update` с полем `type`, либо прямо во вьювере — в панели деталей у
каждой строки есть поле типа, а «Сохранить» отдаёт исправленный `device.json`.
