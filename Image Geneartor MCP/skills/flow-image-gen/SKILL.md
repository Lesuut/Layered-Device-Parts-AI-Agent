# Генерация картинок через Google Flow

MCP-сервер `flow-images` управляет реальным Chrome с открытым Google Flow:
вставляет промт, жмёт генерацию, ждёт результат и качает файлы в 2K.

## Инструменты

| Инструмент | Назначение |
|---|---|
| `flow_check` | Готовность: порт отладки, вкладка Flow, логин. **Вызывать первым.** |
| `flow_setup` | Поднять отладочный Chrome, если не запущен |
| `flow_generate` | Промт (+ референсы) → генерация → ожидание → скачивание. Основной инструмент |
| `flow_paste_reference` | Только вставить референс в композер, без генерации (квота не тратится) |
| `flow_list_files` | Что уже нагенерировано и где лежит |

## Порядок работы

1. **`flow_check`.** Если `ready: true` — сразу генерируй.
2. Если `reason: "chrome_not_running"` — вызови `flow_setup`, потом снова `flow_check`.
3. Если `reason: "login_required"` или `"no_flow_tab"` — **остановись и попроси
   пользователя** войти в Google и открыть проект Flow в отладочном Chrome.
   Сам залогиниться ты не можешь.
4. **`flow_generate`** с промтом.

## Ожидание: вызов блокирующий

`flow_generate` возвращает управление **только когда все картинки готовы и
сохранены на диск**. Внутри уже есть ожидание генерации и апскейла.

- Типичное время: **90–180 секунд** на 4 картинки в 2K.
- НЕ вызывай инструмент повторно, пока предыдущий вызов не вернулся.
- НЕ опрашивай `flow_list_files` в цикле, ожидая появления файлов.
- Не сообщай пользователю об успехе, пока не увидел ответ с `ok: true`.

## Что на выходе

JSON. Ключевые поля:

```json
{
  "ok": true,
  "requested": 4,
  "downloaded": 4,
  "folder": "...\\output\\20260810_235618_exploded_view_...",
  "elapsed_sec": 91.6,
  "images": [
    { "path": "...\\img_01_2k.jpeg", "filename": "img_01_2k.jpeg",
      "bytes": 3178616, "width": 2400, "height": 1792, "upscaled_2k": true }
  ]
}
```

**Все 4 файла отдаются в `images` — это полный список, ничего не остаётся
«в процессе».** Каждый элемент содержит абсолютный `path`, готовый для чтения,
копирования или показа пользователем.

Проверяй результат так:

- `ok: true` и `downloaded == requested` → всё готово, перечисли пользователю
  пути файлов и папку.
- `ok: false` → смотри `error`:
  - `not_logged_in` — попроси пользователя войти в Google;
  - `generation_timeout` — Flow не отдал картинки за отведённое время,
    предложи повторить или подними `gen_timeout`.
- `downloaded < requested` → часть картинок скачалась; скажи об этом честно,
  назови сколько именно и предложи догенерировать.
- `upscaled_2k: false` у файла → сработал откат на 1K (1200×896),
  это не ошибка, но упомяни при отчёте.

## Работа по референсу (image-to-image)

Если у пользователя есть исходная картинка («сделай в этом стиле», «переделай
это фото», «вот пример — нарисуй похожее»), передай её в `reference_images`:

```json
{ "prompt": "exploded view in the same style, white background",
  "reference_images": ["C:\\Users\\...\\ref.png"] }
```

Что делает инструмент под капотом:

1. Вставляет промт в поле ввода Flow.
2. Вставляет картинку в композер — то же, что Ctrl+V (реальное событие paste;
   при неудаче — системный буфер Windows, drag&drop, `input[type=file]`).
3. **Ждёт, пока картинка догрузится на сайт** — миниатюра отрисована, спиннеров
   нет, набор чипов стабилен.
4. **Только после этого** жмёт «Создать».

Правила:

- Формат `reference_images` — список строк: **абсолютные пути** к файлам,
  `data:image/png;base64,...` или http(s)-ссылки. Относительные пути не бери.
- Своя картинка (та, что модель получила в диалоге) — сначала сохрани её
  в файл, потом передай путь. Либо отдай data:-URI напрямую.
- Референсов можно несколько — вставятся по очереди.
- Если референс вставить не удалось, генерация **не запускается**:
  вернётся `error: "reference_upload_failed"`, квота не тратится.
  Тогда покажи пользователю поле `references[].errors` и предложи проверить
  вручную через `flow_paste_reference`.
- `error: "no_prompt_box"` — открыт лендинг Flow, а не проект. Попроси
  пользователя открыть проект во вкладке.
- В ответе `flow_generate` появляется поле `references` — по каждому
  референсу `name`, `ok`, `method` (каким способом вставился).

## Параметры

- `prompt` — текст промта. Английский даёт результат стабильнее русского.
- `reference_images` — список картинок-референсов (см. выше). По умолчанию нет.
- `ref_method` — `auto` (по умолчанию: paste → clipboard → drop → upload).
  Явно указывай только при разборе проблем: `clipboard` — настоящий Ctrl+V
  через системный буфер Windows, `upload` — через `input[type=file]`.
- `ref_timeout` — сколько ждать загрузку референса, сек (90).
- `count` — сколько картинок ждать, по умолчанию 4 (Flow настроен на x4).
- `quality` — `2k` по умолчанию (2400×1792, с апскейлом), `1k`, `src`
  (быстро, 1200×896, без меню), `4k` (требует платного тарифа — упрётся в заглушку).
- `out_dir` — куда сохранить. По умолчанию папка `output` рядом с сервером.
  Если пользователь назвал папку — передай её явно.
- `gen_timeout` (600 с), `ui_timeout` (180 с) — трогай только при таймаутах.

## Промты

Работает Nano Banana 2. Что даёт хороший результат:

- Английский, конкретика по предмету и стилю.
- Для раскладок устройств: `exploded view teardown of <предмет>, all internal
  parts laid out flat, technical illustration, light background`.
- Дописывай фон и стиль явно (`white background`, `technical illustration`,
  `isometric`, `studio lighting`) — иначе Flow выбирает сам.
- Один вызов = один промт = 4 варианта одной идеи. Нужны разные идеи —
  делай несколько последовательных вызовов, не пытайся склеить в один промт.

## Ограничения

- Chrome с профилем `ChromeDebugProfile` должен быть запущен и залогинен.
  Обычный Chrome пользователя закрывать не нужно — это отдельный процесс.
- Пока идёт генерация, не трогай эту вкладку Chrome другими инструментами.
- Каждый вызов расходует квоту Google Flow пользователя. Не гоняй генерацию
  «на пробу» без запроса — для проверки работоспособности есть `flow_check`.
