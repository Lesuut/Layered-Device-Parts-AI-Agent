# Конвейер: фото устройства → игровой 2D-ассет

Игра: устройство разбирается послойно (передняя панель → клавиатура → плата →
батарея → задняя крышка), детали чистятся/заменяются, потом собирается обратно.
Значит ассет должен быть **послойным, вид сверху, детали не перекрываются
в атласе, а по позициям складываются в цельное устройство**.

## Сначала: какой это запрос

1. **Технический / по проекту** — правки кода, вопросы, доработки тулз.
   Конвейер не запускать, работать как обычно.
2. **Есть картинка устройства** (путь к файлу или ссылка) — запускать конвейер
   ниже целиком.

Если непонятно, что за запрос — спроси одной фразой, не выдумывай.

## Карта инструментов

| Сервер | Инструменты | Роль |
|---|---|---|
| `flow-images` | `flow_check`, `flow_generate` | генерация картинок в Google Flow по промту + референсу |
| `bg-remover` | `bg_check`, `bg_remove` | удаление белого фона → PNG с альфой |
| `asset-builder` | `asset_extract`, `asset_punch`, `asset_pack`, `asset_render`, `asset_update`, `asset_validate`, `asset_viewer`, `asset_package` | нарезка деталей, атлас, сборка, упаковка |

Промты лежат в `Promts/`, менять их без запроса нельзя:
- `Promts/2 Device to burger.txt` — устройство → изометрическая «взрыв-схема» (бургер)
- `Promts/3 Burger to parts.txt` — бургер → плоская раскладка деталей вид сверху

Рабочие папки: промежуточное в `work/<device>/`, готовое в `assets/<device>/`.

## Шаги

### 0. Проверка окружения
`flow_check`. Если `ready: false` — скажи пользователю, что нужно (войти в
Google / открыть проект Flow) и остановись. Сам залогиниться не можешь.

### 1. Устройство → бургер
`flow_generate` с текстом из `Promts/2 Device to burger.txt` и
`reference_images: [<картинка пользователя>]`, `count: 4`.

Референс обязателен — без него Flow нарисует чужое устройство.

### 2. Выбрать лучший бургер (глазами)
Прочитай все 4 картинки через Read и оцени по критериям:

| Критерий | Плохо | Хорошо |
|---|---|---|
| Текст, цифры, подписи | есть заголовок/номера/выноски | голая схема без единой буквы |
| Полнота разбора | детали слиплись, корпус целый | все слои раздельно |
| Узнаваемость | другое устройство | то же, что на референсе |
| Ракурс | сильная перспектива, детали боком | ровная изометрия, детали читаемы |
| Стиль | фотореализм, шум | чистый лайн-арт с плоской заливкой |

Выбери одну лучшую. **Если все четыре плохие — перегенерируй** (ещё один
`flow_generate` с тем же промтом и референсом), но не больше двух повторов:
каждый вызов тратит квоту пользователя. Скажи пользователю, что перегенерируешь
и почему.

Наличие текста на бургере — не приговор: на следующем шаге он обычно исчезает.
Приговор — слипшиеся детали и неверное устройство.

### 3. Бургер → раскладка деталей
`flow_generate` с текстом из `Promts/3 Burger to parts.txt`,
`reference_images: [<выбранный бургер>]`, `count: 4`.

### 4. Удалить фон
`bg_remove` со всеми 4 картинками, `method: "white"`, `out_dir: work/<device>/cut`.
`trim` НЕ включать: координаты деталей ещё понадобятся.

Проверь `opaque_share`: около 0.3–0.7 нормально. Ближе к 1 — фон не снялся,
подними `tol_bg` до 16–20 и повтори.

### 5. Нарезать детали
`asset_extract` по всем 4 PNG в `work/<device>/parts`.
**Обязательно открой `contact_sheet.png` через Read.** На нём каждая деталь
подписана `#N` и размером.

### 6. Выбрать детали (главный шаг, только глазами)
Из всех 4 вариантов собери ОДИН комплект. Правила:

- **Мусор выкинуть**: обрывки букв заголовка, тени, рамки, дубли одной детали,
  куски, где две детали слиплись, целиком собранное устройство.
- **Комплект для телефона** (типовой, снизу вверх):
  `back_cover` → `rear_chassis` → `battery` → `main_pcb` → `keypad_membrane`
  → `keypad` → `screen` → `front_shell`.
  Для других устройств см. `references/part_taxonomy.md`.
- Детали бери **из разных картинок свободно** — важно не единство источника,
  а чтобы они стыковались по форме и размеру между собой.
- Проверь пропорции: батарея должна влезать в корпус, плата — в шасси,
  клавиатура — в вырезы передней панели. Если у детали пропорции не бьются
  с остальными — бери такую же с другой картинки.
- Мелочь (винты, пружины, микрофон, динамик, камера) добавляй только если
  она читаемая и нужна геймплею. Десяток одинаковых винтов не нужен.
- Дай каждой детали `id` латиницей в snake_case и человекочитаемое `name`.

### 7. Пробить вырезы
`asset_punch` для корпусов и передних панелей: вырез под экран, дырки под
клавиши, отверстия винтов должны стать сквозными.
НЕ применять к светлым деталям (белая мембрана, наклейка батареи).
После — глянь деталь глазами, `punched_share` больше ~0.5 подозрительна.

### 8. Атлас и сборка
`asset_pack` со списком деталей в порядке слоёв (`layer` 0 = самый низ).

Начальные позиции ставь осмысленно, не все в центр: батарея ниже центра,
плата по центру, клавиатура в нижней трети, экран в верхней.

### 9. Цикл сборки: рендер → правка → рендер
1. `asset_render` mode=`flat` → **открой превью через Read**.
2. Смотри: клавиши попадают в отверстия? экран в вырез? батарея в отсек?
   деталь не торчит за корпус? порядок слоёв верный?
3. `asset_update` с `dx`/`dy`/`size`/`rotation` — правь то, что съехало.
4. Повтори. Обычно 2–4 итерации. Не сдавай кривую сборку.

Порядок сборки в цикле: сначала поставь нижнюю деталь (задняя крышка) в центр
холста, затем каждый следующий слой подгоняй **относительно уже стоящих**.

Полезно: `asset_render` mode=`exploded` — видно порядок слоёв целиком.

### 10. Проверка и упаковка
`asset_validate` — должно быть `ok: true` (пересечение кадров в атласе
недопустимо). Затем `asset_package` в `assets/<device>/`.

Покажи пользователю: путь к папке, число деталей, размер атласа, и что
**`ОТКРЫТЬ_<device>.html` открывается двойным кликом** — ассет вшит внутрь,
перетаскивать ничего не надо. Рядом лежит `viewer.html` — в него можно
перетащить любой другой ассет.

Если ассет поправили после упаковки — пересобери просмотрщик через
`asset_viewer`, иначе в нём останется старая сборка.

## Формат device.json

```json
{
  "device": "nokia_3310",
  "texture": "texture.png",
  "texture_size": [1279, 1577],
  "canvas": [595, 1336],
  "parts": [
    {
      "id": "back_cover", "name": "Back Cover",
      "frame": { "x": 3, "y": 847, "w": 362, "h": 730 },
      "corners": [[3,847],[365,847],[365,1577],[3,1577]],
      "uv": [0.002346, 0.537095, 0.285379, 1.0],
      "pivot": [0.5, 0.5],
      "position": [300, 570], "size": [362, 730],
      "scale": 1.0, "rotation": 0.0, "layer": 0
    }
  ]
}
```

`frame` — откуда резать из текстуры. `position` — центр детали на холсте
сборки. `layer` — порядок отрисовки и порядок разборки в игре.

## Чего не делать

- Не запускать `flow_generate` без референса, когда пользователь дал картинку.
- Не гонять генерацию «на пробу»: каждый вызов тратит квоту Flow.
- Не собирать ассет из деталей, которые не проверил глазами.
- Не отдавать результат, не посмотрев финальный `preview_flat.png`.
- Не править файлы в `Promts/` без явной просьбы.
- Не выдавать частичный результат за готовый: если деталей не хватает
  (нет экрана, нет платы) — скажи об этом прямо.
